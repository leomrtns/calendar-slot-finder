# Obtaining a private Outlook calendar snapshot
Checked against Microsoft's public documentation on 24 September 2026. This concerns Outlook on the web for Microsoft 365/Exchange Online and Outlook.com, including the web interface referred to as Outlook.cloud. Your organisation may further restrict desktop access or API consent.
## Web interface limitation
I could not verify a Microsoft-documented private whole-calendar `.ics` download button in the web interface. Microsoft's documented web ICS route is calendar publishing, which makes the published calendar accessible to anyone with its link. This does not meet your requirement, and temporarily publishing and then unpublishing is not a private export route. See [Share your calendar in Outlook on the web](https://support.microsoft.com/en-us/outlook/share-your-calendar-in-outlook-on-the-web).
This conclusion describes the documented supported workflow; it is not a claim that every tenant's interface has been inspected. An attachment for a single meeting is not a semester snapshot. Changing hidden URLs or copying browser session tokens is not a documented export method.
## Supported private ICS file route: classic Outlook for Windows
If your institution permits access through classic Outlook for Windows, synchronise the calendar there, select it, and choose **File → Save Calendar → More Options**. Specify the semester's date range, choose the appropriate detail level, and save the `.ics` file locally. Repeat for other calendars that should block your time. Stop after saving: there is no need to import it into Google or share it anywhere.
Microsoft documents these steps in [Export an Outlook calendar to Google Calendar](https://support.microsoft.com/en-us/office/export-an-outlook-calendar-to-google-calendar-662fa3bb-0794-4b18-add8-9968b665f4e6); the initial export creates the local file independently of the later Google-import steps. This is a desktop alternative, not a menu available in the web interface. Ensure private appointments are included as occupied time and verify that your chosen detail/export settings preserve the busy/free information you need.
## If you only have web access: authenticated Microsoft Graph
Microsoft Graph offers an authenticated read route without publishing. Its `calendarView` endpoint returns single events, recurrence occurrences and exceptions over a specified range. For the signed-in user's default calendar:
```text
GET https://graph.microsoft.com/v1.0/me/calendar/calendarView?startDateTime=2026-09-21T00:00:00%2B01:00&endDateTime=2026-12-12T00:00:00Z
```
These example boundaries include the final day of an example autumn semester and specify the correct London offset at each boundary. The least-privileged delegated permission documented for this endpoint is `Calendars.ReadBasic`. Sign-in/app consent must follow your institution's policy. Fetch every `@odata.nextLink` page and repeat for additional calendars. The response is JSON, not an ICS download. A separate approved exporter must convert the returned occurrences to standalone ICS events, preserving start/end times, all-day status, cancellation and `showAs` free/tentative status. The tool in this project reads local ICS; it does not implement authentication or that Graph conversion.
See Microsoft's [List calendarView](https://learn.microsoft.com/en-us/graph/api/calendar-list-calendarview?view=graph-rest-1.0) for permissions, date boundaries, timezone headers and paging.
For your web-only, publishing-disabled account, the practical supported next step is to ask institutional IT for an approved local ICS export or an approved authenticated Graph export. If both desktop export and API access are unavailable, I have not found a documented private whole-calendar ICS export from the browser alone. This limitation does not require installing an Outlook connector or granting this tool access to your account.
